# 开发流程规范（6阶段TDD）

> **AI Agent必须严格遵守此流程！**

## 📋 6阶段工作流程

### 阶段1：任务分析与规划 📊
**目标**：理解需求，拆分子任务

**执行步骤**：
1. 仔细阅读任务描述
2. 识别涉及的DDD分层
3. 列出需要创建/修改的领域对象
4. 将大任务拆分为独立子任务（每个子任务不超过3个文件）
5. 生成作战计划文档到 `task/{任务名称}/{任务名称}TaskPlan.md`

**输出**：作战计划文档

---

### 阶段2：编写失败的测试（红灯）🔴
**目标**：先写测试，定义期望行为

**执行步骤**：
1. 根据任务创建Spock测试文件
2. 测试必须覆盖：正常路径、失败路径、边界条件
3. **不要创建任何实现代码**
4. 提交信息格式：`FAILING TEST: [子任务描述]`
5. Git commit 仅包含测试文件

**检查清单**：
- [ ] 测试文件已创建，命名正确（`*Spec.groovy`）
- [ ] 测试方法以`should`开头
- [ ] 包含given-when-then结构
- [ ] 包含负面测试（null、异常、业务规则拒绝）
- [ ] 没有创建实现代码
- [ ] Git commit已提交

---

### 阶段3：最小实现（绿灯）🟢
**目标**：刚好让测试通过的最少代码

**执行步骤**：
1. 根据测试，编写最小实现代码
2. **严格遵守**DDD分层依赖规则
3. 不要添加额外功能（不要"顺便"做）
4. 本地运行`mvn test`确保全部通过
5. 提交信息格式：`IMPLEMENT: [子任务描述]`

**检查清单**：
- [ ] 代码放在正确的包内
- [ ] 没有违反架构约束
- [ ] 所有测试通过（mvn test）
- [ ] 没有添加额外功能
- [ ] Git commit已提交

---

### 阶段4：重构与审查（清洁）🧹
**目标**：在不改变行为的前提下优化代码

**执行步骤**：
1. 在测试保护下进行重构
2. 消除重复代码
3. 改善命名，使其体现业务意图
4. 确保代码在正确的包内
5. 再次运行全部测试确保通过
6. 提交信息格式：`REFACTOR: [重构说明]`

**检查清单**：
- [ ] 没有改变业务行为
- [ ] 代码更清晰易读
- [ ] 没有重复代码
- [ ] 所有测试通过
- [ ] Git commit已提交

---

### 阶段5：端到端验证 ✅
**目标**：确保功能在所有层次正确集成

**执行步骤**：
1. 如果涉及跨层协作，编写或执行集成测试（`*IT.groovy`）
2. 对于Web接口，使用curl或浏览器验证真实响应
3. 确保MyBatis-Plus操作实际生效（不要只mock）
4. 运行`mvn verify`确保所有测试通过

**检查清单**：
- [ ] 集成测试通过
- [ ] 手动验证功能正常
- [ ] 数据库操作正确
- [ ] 没有破坏现有功能

---

### 阶段6：文档同步与宣布完成 📝
**目标**：更新文档，宣布任务完成

**执行步骤**：
1. 检查本次改动是否需要更新文档
2. 列出所有完成的子任务
3. 列出通过的测试数量
4. 说明任何已知限制
5. 宣布任务完成

**检查清单**：
- [ ] 相关文档已更新
- [ ] 任务清单已标记完成
- [ ] 已知限制已说明
- [ ] 任务已宣布完成

---

## 🚨 红线规则（绝对不能违反）

| # | 规则 | 后果 |
|---|------|------|
| 1 | 绝对不能在阶段2前写实现代码 | PR被拒绝，任务重置 |
| 2 | 提交的代码必须通过ArchUnit测试 | 根据失败日志修正分层违规 |
| 3 | 测试必须包含负面场景 | 反馈循环强制重写测试 |
| 4 | 一个commit不能同时包含测试和实现 | 任务被打回，必须拆分 |
| 5 | 不能自创架构规则 | 视为架构漂移，任务暂停 |

```markdown

- [ ] 子任务1：实现核心领域逻辑
  - [ ] 新建Order聚合根
  - [ ] 新建OrderRepository接口
  - [ ] 编写OrderSpec测试
  - [ ] 关键测试：库存不足时抛出InsufficientStockException

- [ ] 子任务2：实现应用服务编排
  - [ ] 新建CreateOrderCommand
  - [ ] 新建OrderApplicationService
  - [ ] 编写OrderApplicationServiceSpec测试

## 风险与依赖
- [ ] 依赖：User领域服务
- [ ] 风险：库存服务可能超时
```
